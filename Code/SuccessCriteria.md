# FairShare Success Criteria (Criterion A)

1. The system shall provide secure login functionality for both members and administrators using unique usernames and encrypted passwords.
2. The system shall store all member information in a relational database without data duplication.
3. The system shall record member visits, facility usage and purchases, including the date, service used and transaction value.
4. The system shall automatically calculate each member's engagement score based on configurable factors such as visits, spending and guest referrals.
5. The system shall automatically generate personalised discounts based on the calculated engagement score without administrator intervention.
6. The system shall display each member's current reward status, engagement score and available discounts on their dashboard.
7. The system shall create a unique user ID barcode for the user to scan in and out of facilities.
8. The system shall track facility usage and calculate usage duration using timestamp data.
9. The facility should let users be able to create guest id that tracks guest visits and spending, if they do not have an ID.
10. The system shall provide an administrative control panel allowing club managers to update algorithm weighting factors, set profit-sharing pool amounts, and view/edit member records.
11. The system shall allow members to generate a unique redemption QR code or coupon code on their mobile device to apply earned discounts during a transaction.
12. The system shall feature a responsive UI layout that automatically adjusts for seamless navigation across mobile phones, tablets, and desktop displays.
13. The system shall maintain low page-loading times (under 2–3 seconds) on mobile cellular connections through optimised asset caching.
14. The system shall generate visual charts/graphs for administrators showing overall facility usage trends, peak activity hours, and total rewards distributed.
15. The system shall allow administrators to export member usage logs and financial reward summaries into CSV format for record-keeping.
16. The system shall implement client- and server-side validation to prevent duplicate registrations, negative transaction entries, and unauthorised access to administrative pages.
